# 02 — Deployment & Infrastructure

Everything needed to stand the server side back up. Pair this with [10-rebuild-runbook.md](10-rebuild-runbook.md) for the ordered checklist.

## Server prerequisites

- **Windows Server** with **IIS** and the **Classic ASP** role/feature installed (ASP is not installed by default).
- **.NET / CDO**: the mail features use `CDO.Message` (built into Windows). No extra install.
- **PowerShell 5.1+** for the scheduled jobs.
- **NinjaOneDocs** PowerShell module on the machine that runs the NinjaOne jobs (the scripts auto-install it to CurrentUser scope if missing).
- Outbound network access from the server to: `api.github.com`, `raw.githubusercontent.com`, `api.cloudflare.com`, the NinjaOne instance (`baldwincountyal.rmmservices.net`), `outlook.office365.com` (calendar ICS), and the Exchange relay host (see external services).

## IIS site configuration

1. Create a site (or app) whose physical path is the web root, e.g. `C:\inetpub\wwwroot\`.
2. Put `default.asp` at the site root. Ensure `default.asp` is in the default-document list.
3. **Enable Classic ASP.** In IIS Manager → the site → **ASP**, set:
   - **Send Errors To Browser**: `False` in production (avoids leaking VBScript errors).
   - **Enable Parent Paths**: only if needed; the app uses `Server.MapPath` for `printlist.csv`, which does not require parent paths.
   - Script timeout: default is fine.
4. **App pool identity**: note which identity the pool runs as. This identity must be able to **read** every cache directory (below). It's the account the diagnostics endpoint reports; keep it least-privilege.
5. **HTTPS**: TLS is normally terminated at App Proxy, but bind a cert on the origin too if the origin is reachable on the network.

## Entra ID / Azure AD Application Proxy

The app is published to the internet through App Proxy and relies on it for identity.

1. **App Registration** with three **App Roles**: `SecOps.View`, `CIS.Admin`, `Tech.Basic`. Assign users/groups to roles in the Enterprise Application.
2. **Application Proxy application** pointing at the internal IIS origin. Internal URL is the origin (e.g. `https://toolkit.internal.co.baldwin.al.us/`); external URL is the `…msappproxy.net` address (currently `baldwincountycistoolkit-baldwincountyalgov.msappproxy.net`).
3. **Pre-authentication**: Entra ID.
4. **Header pass-through**: App Proxy / Entra must forward the app-role claims as the **`X-MS-APP-ROLES`** request header (lower-cased role names, e.g. `secops.view cis.admin`). The app reads this header for all authorization.
5. **Injected shared secret**: App Proxy is configured to add **`X-BCC-PROXY-SECRET`** with the value that matches `PROXY_SECRET` in `default.asp`. This lets the origin reject any request that didn't come through App Proxy. (See the ordering caveat in [09-security.md](09-security.md).)

If you rotate `PROXY_SECRET`, you must update it in **both** the App Proxy header rule and `default.asp`.

## Directory layout on the server

Create these directories and set permissions. **The recurring gotcha:** the IIS app-pool identity (which *reads*) and the scheduled-task account (which *writes*) are usually different accounts. Both need the right access on the same folders.

| Path | Written by | Read by | Contents |
|------|-----------|---------|----------|
| `C:\inetpub\wwwroot\` | deploy | IIS | `default.asp`, `printlist.csv`, `tools\orgchart.csv` |
| `C:\inetpub\serv\` | scheduled jobs / admins | IIS app pool | `list.csv`, `poc-people.csv`, `ai-logs\` |
| `C:\inetpub\serv\ai-logs\` | `Build-AiLogsCache.ps1` | IIS app pool | `ai-logs-index.json`, `ai-logs-YYYY-MM-DD.json` |
| `C:\inetpub\reports\` | scheduled jobs | IIS app pool | `warranty.json` |
| `C:\inetpub\reports\ninja\` | Ninja report jobs | IIS app pool | `ninja-YYYY-MM.json` |
| `C:\inetpub\secrets\` | admins only | scheduled tasks | API tokens/secrets (see below) |
| `C:\inetpub\logs\` | scheduled jobs | admins | job logs (`ninja-report-*.log`) |

Permission rules of thumb:
- `C:\inetpub\serv\`, `C:\inetpub\reports\` (and `\ninja`): **IIS app-pool identity = Read**; **scheduled-task account = Modify/Write**.
- `C:\inetpub\secrets\`: readable **only** by the scheduled-task accounts and admins — **not** the IIS app pool, and never inside the web root.
- `C:\inetpub\wwwroot\tools\orgchart.csv` currently sits **inside** the web root and is therefore directly fetchable by any authenticated user. See the security doc; consider moving it to `serv\` and serving it only through the gated handler.

## Data files the app expects

These are not generated by the app; provide them or the relevant pane shows a "not found" message.

- `C:\inetpub\serv\list.csv` — device monitor list, columns `Name,Type,IP`. Drives the At-a-Glance Systems card and Internal Systems Status.
- `C:\inetpub\serv\poc-people.csv` — points-of-contact roster (At-a-Glance).
- `C:\inetpub\wwwroot\printlist.csv` — printer list for the Printer Pass tool (`Server.MapPath("printlist.csv")`). Generated by an export script.
- `C:\inetpub\wwwroot\tools\orgchart.csv` — org chart roster (name, title, manager, ext, cell, email).

## Secrets

Plain-text token files under `C:\inetpub\secrets\`:

| File | Used by | For |
|------|---------|-----|
| `gh-ai-token.txt` | `Build-AiLogsCache.ps1` | GitHub PAT to read the AI logs repo |
| `gh-edit-token.txt` | `ghEdit` handler | GitHub PAT to commit edits to link JSONs |
| `ticketfeedback.txt` | `Send-TicketFeedbackReport.ps1` | GitHub PAT for the ticket-feedback repo |
| `clouddnsviewapi.txt` | Cloudflare handlers | Cloudflare API token (DNS + analytics read) |
| `ninja-clientsecret.txt` | Ninja report jobs | NinjaOne OAuth client secret |

**Token expiry is the top operational risk.** Two outages in this system's history (AI logs freezing, ticket-feedback token "not found") traced back to token/permission problems. Recommended: add an expiry check to each job that emails a warning ~14 days out, and/or migrate secrets to **Azure Key Vault** with a managed identity. See [07-external-services.md](07-external-services.md).

## Deploying an update

1. Edit `default.asp` (and/or the JSON config or PS scripts) in the `toolkit` repo.
2. Copy `default.asp` to the site root. No restart needed — Classic ASP recompiles per-request.
3. If you changed a scheduled script, update the copy the Task Scheduler runs (e.g. `C:\Scripts\`).
4. For link-tile / scripts / org chart changes, commit the JSON/CSV to GitHub (or edit via the in-app editor, which commits through the `ghEdit` handler). No redeploy of `default.asp` is required for content changes.

## Verifying a deployment

- Load the page as a SecOps user; confirm the footer version matches `version.json`.
- Open **Report Center → Ninja Reporting**; confirm months list and a month loads.
- Open **At a Glance**; confirm the Systems card and calendar populate (device list + ICS reachable).
- Confirm the three roles gate correctly by testing with a Tech.Basic-only account (no Report Center, no SecOps/SysAdmin).
